# Java / Python API parity

Pinned Java jdk-16 commit `833f2dd9a581a1984129b3f709f63afe3bfdc124`; 301 overloads.

Every operation is available on all four clients. Async methods are native coroutines; smart clients route the same method signatures.
String keys use UTF-8. Existing Python positional arguments and successful bytes, bool, int, dict, list, LockStatus and CasResult results are preserved.
`add_element_ordered` retains its count result; `add_element_ordered_set` supplies the separate boolean convenience.
Optional hint/client-ID/timeout/TTL overloads use Python defaults. TTL is milliseconds; lock duration and timeout are seconds.
Jedis and application-level replication are excluded. Replication wire messages and stubs are included.

## Standalone-wrapper behavior and compatibility adaptations

The pinned `FastCacheAsyncStandaloneClient` owns collection creation chunking:
one create, then tail additions for list/vector/queue, unpositioned additions for
sets, weighted additions for ordered sets, and paired additions for maps.
It transfers the create response hint into subsequent requests. Both clients
preflight complete serialized requests and continuation hints and retain a single
creation expiration across all chunks, including map values and ordered elements.
These are correctness adaptations where the Java wrapper estimates request sizes
and rebuilds continuation values without the initial element expiration.

Head/tail and relative-pivot RPCs return integer counts in the pinned schema.
Retained boolean APIs are compatibility adaptations: empty input succeeds,
positive chunk counts succeed, and zero stops with acknowledged partial progress.
Count APIs sum integer responses, return zero for empty input, and reject overflow.
Front aliases, generic addition and ordered boolean conveniences are retained
compatibility APIs even where Java removed their names. Python's pre-existing
`add_element_ordered` remains count-returning.

Weighted point reads and removals both use configured routing, as does the new
ordered-map range. Explicit caller-local overrides take precedence. No operation
replays after acknowledged progress; fallback/reroute is limited to one attempt.
